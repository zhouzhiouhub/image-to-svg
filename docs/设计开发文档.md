## 1. 项目概述

### 1.1 背景

图标、Logo、线稿类位图在网页中难以无损缩放，内联 SVG 则可以任意分辨率清晰渲染，并减少小图请求。同时，设计交付、社交媒体、邮件等场景仍需要 PNG / JPEG / WebP 位图。浏览器已经同时具备：

- **位图 → 矢量**：将解码后的像素描摹为路径（tracing）
- **矢量 → 位图**：将 SVG 栅格化后编码为 PNG / JPEG / WebP（rasterize）

本工具把这两条能力做成可视化、纯前端的本地转换器。

### 1.2 目标

做一个 **可视化图片格式转换工具（Web 应用）**，核心是位图 ↔ SVG：

- 用户通过 **拖拽 / 粘贴 / 文件选择** 三种方式输入
- **位图输入**：描摹为 SVG，可调参数、对比预览、下载 / 复制代码
- **SVG 输入或 SVG 结果**：栅格化为 PNG / JPEG / WebP，可调尺寸、质量、背景
- **明确告知用户哪些类型不能转换、为什么**，而不是静默失败

### 1.3 核心价值

| 价值点 | 说明 |
|---|---|
| 无损缩放 | 图标、Logo 转矢量后任意分辨率清晰渲染 |
| 双向导出 | 得到 SVG 后仍可按目标平台导出 PNG / JPEG / WebP |
| 体积可控 | 单色小图标转 SVG 后体积通常小于位图 |
| 零部署门槛 | 纯前端方案，转换在浏览器本地完成，图片不离开设备 |

## 2. 功能需求

### 2.1 两条转换链路（按输入自动分流）

```
位图（PNG/JPG/WebP/BMP/静态 GIF）
  → 格式校验 → 解码为像素 → 灰度/二值化 → 描摹 → SVG
  → 预览 / 下载 .svg / 复制代码
  → 【可选】把该 SVG 再栅格化为 PNG / JPEG / WebP

SVG 文件或 SVG 代码
  → XML/结构校验 → 栅格化到 Canvas
  → PNG / JPEG / WebP Blob
  → 预览 / 下载（可调倍率、质量、背景）
```

- 转换完全在 **浏览器端** 完成，不依赖服务端
- 位图描摹参数实时可调，调节后 **即时重新转换并预览**
- SVG 栅格化参数（格式 / 倍率 / 质量 / 背景）调节后即时重导

### 2.2 图片输入（三种方式，全支持）

| 输入方式 | 交互 | 技术实现 |
|---|---|---|
| **拖拽上传** | 拖入页面中央上传区，区域高亮反馈 | Element Plus `el-upload` 组件 `drag` 模式 |
| **剪贴板粘贴** | 页面内 `Ctrl/Cmd + V` 粘贴截图或 SVG 文本 | 监听 `paste` 事件：`image/*` 走位图链路；纯文本若为 `<svg` 走栅格化链路 |
| **文件选择** | 点击上传区唤起系统文件选择器 | Element Plus `el-upload` 默认点击行为 |
| 粘贴 URL 链接 | 粘贴图片地址自动拉取（可选，P2） | 检测粘贴内容为 URL 时 fetch 拉取 |

### 2.3 位图 → SVG 参数（描摹）

| 参数 | 含义 | 默认值 | UI 组件 |
|---|---|---|---|
| threshold | 二值化阈值（0–255） | 默认自动 | `el-slider`，勾选「自动」时禁用 |
| colorMode | 黑白 / 多色（posterize 分层） | 黑白 | `el-radio-group` |
| steps | 多色模式的色彩层数（2–8） | 4 | `el-input-number`（仅多色模式显示） |
| turdSize | 去噪：小于该面积的斑点被清除 | 2 | `el-input-number` |
| optTolerance / alphaMax | 曲线拟合精度（进阶） | 默认 | 折叠面板内（渐进披露） |

### 2.4 SVG → 位图参数（栅格化）

| 参数 | 含义 | 默认值 | UI 组件 |
|---|---|---|---|
| format | 输出格式 | PNG | `el-radio-group`：PNG / JPEG / WebP |
| scale | 导出倍率（相对 viewBox / 固有尺寸） | 2× | `el-radio-group`：1× / 2× / 3× / 自定义 |
| quality | JPEG / WebP 有损质量（0.1–1） | 0.92 | `el-slider`（仅 JPEG / WebP 显示） |
| background | 画布背景 | 透明（JPEG 强制实色） | 透明 / 白色 / 自定义色；选 JPEG 时禁用透明 |

格式能力以浏览器 Canvas 编码器为准（见 4.5），不引入额外编码库。

### 2.5 结果管理

- 左右对比视图：原图 ｜ 转换结果（支持透明/网格背景切换）
- 显示关键指标：原文件体积 vs 结果体积、路径数（仅 SVG）、宽高
- 操作：
  - 位图链路：**下载 .svg**、**复制 SVG 代码**、**再导出为 PNG / JPEG / WebP**
  - SVG 链路：**下载当前格式**、切换格式即时重导
- 批量转换（P2）、会话内历史记录（P2）

## 3. 图片类型支持说明（重点）

### 3.1 作为「位图 → SVG」输入

| 格式 | 支持度 | 处理方式 |
|---|---|---|
| **PNG** | ✅ 最佳（核心场景） | 解码后进入描摹；透明通道参与阈值计算 |
| JPG / JPEG | ✅ 支持 | `createImageBitmap` / `Image` 解码 → 像素 → 描摹（无透明通道） |
| WebP（静态） | ✅ 支持 | 同 JPG 路径，主流浏览器均可解码 |
| BMP | ✅ 支持 | 同上 |
| GIF（单帧/静态） | ⚠️ 有限支持 | 只取 **第一帧** 转换，需在结果中明确提示 |

### 3.2 作为「SVG → 位图」输入

| 格式 | 支持度 | 处理方式 |
|---|---|---|
| **SVG（静态、自闭合资源）** | ✅ 支持 | 浏览器渲染引擎栅格化 → Canvas 编码为 PNG / JPEG / WebP |
| 含外链图片 / 外链样式的 SVG | ❌ 拒绝或降级 | Canvas 同源策略会污染画布，`toBlob` 抛 `SecurityError`。提示：「请使用内联资源的 SVG（图片请转 data URI）」 |
| 动画 SVG（SMIL / CSS 动画） | ⚠️ 有限支持 | 只捕获当前静态帧，动画会丢失。提示：「仅导出静态画面」 |

**浏览器可导出的位图格式（已核实，2026-08）：**

| 目标格式 | MIME | 透明通道 | 说明 |
|---|---|---|---|
| PNG | `image/png` | ✅ | 规范强制支持，默认回退格式 |
| JPEG | `image/jpeg` | ❌ | 有损；必须先铺实色背景 |
| WebP | `image/webp` | ✅ | 现代浏览器广泛支持；导出后必须校验 `blob.type`，不支持时静默变成 PNG |

不承诺 AVIF / BMP / ICO / GIF 动画导出：Canvas 对这些格式要么不编码、要么静默回退成 PNG。

### 3.3 不能 / 不适合的类型（界面必须明确提示原因）

| 类型 | 判定 | 原因说明 |
|---|---|---|
| **动图（GIF 动画 / APNG / 动态 WebP）** | ❌ 拒绝描摹 | 描摹输出是 **静态矢量路径**，动画帧会全部丢失。提示语：「动图暂不支持转换，仅支持静态图片」 |
| **AI / EPS / PDF** | ❌ 拒绝 | 浏览器无法把这些格式解码为可用位图或 SVG DOM。提示语：「仅支持 PNG / JPG / WebP / BMP / 静态 GIF / SVG」 |
| **把 SVG 再描摹成 SVG** | ❌ 拒绝该路径 | SVG 已是矢量；用户若上传 SVG，自动走 **栅格化导出**，不走描摹。提示语：「已检测到 SVG，将导出为 PNG / JPEG / WebP」 |
| **照片类高分辨率彩色图片** | ⚠️ 强提示不推荐描摹 | 技术上可转，但会产生海量贝塞尔曲线：体积暴涨、渲染卡顿、观感劣化。不禁止，上传时警告 |
| **非图片文件（DOCX / ZIP / MP4 / MP3 等）** | ❌ 拒绝 | 无法解码。提示语：「仅支持 PNG / JPG / WebP / BMP / 静态 GIF / SVG」 |
| **超大尺寸（> 4096px 或 > 20MB）** | ❌ 拒绝 | 描摹或大倍率栅格化耗时过长，存在卡死风险 |

### 3.4 格式校验规则

```
accept: image/png, image/jpeg, image/webp, image/bmp, image/gif, image/svg+xml
校验顺序：扩展名 → MIME type → 解码 / XML 探测（防伪造扩展名）
分流：image/svg+xml 或内容以 <svg 开头 → 栅格化链路；其余位图 → 描摹链路
动图检测：GIF 解码后帧数 > 1 即判定为动图
WebP 导出：toBlob 之后若 blob.type !== 请求类型，提示当前浏览器不支持该编码并回退 PNG
```

### 3.5 适用边界（写进产品文案）

本工具定位是 **图标 / Logo / 线稿类位图 ↔ SVG** 的本地转换器。

- 不适合替代矢量重绘（AI 矢量化方案）
- 不适合照片矢量化
- SVG 栅格化是「按像素拍一张静态图」，不是保留矢量可编辑性

## 4. 技术方案

### 4.1 选型原则

**尽量使用成熟库与浏览器原语，减少自实现**。必须自写的只有：粘贴分流、格式校验、两条转换流水线的参数组装。

`reference/` 中的 Vite 插件、Node 端 `potrace` 调用、构建期目录扫描与 `data-src` 替换，**均不进入本系统实现**。

### 4.2 技术栈

| 层 | 选型 | 理由（独立于参考项目） |
|---|---|---|
| 框架 | **Vue 3 + TypeScript + Vite** | 组件化 SPA、类型安全、开发体验成熟，适合工具类单页 |
| UI 组件库 | **Element Plus** | 中文文档完善；上传、滑条、单选、数字输入、提示、折叠面板覆盖界面需求 |
| 位图 → SVG | **potrace 的浏览器 WASM 发行版**（`esm-potrace-wasm` 或同类） | 浏览器内描摹；提供 `trace()` / `posterize()`；不引入 Node 文件 API |
| SVG → 位图 | **浏览器原生 Canvas** | 无需编码库。`Image`/`createImageBitmap` 渲染 SVG，`canvas.toBlob` / `OffscreenCanvas.convertToBlob` 导出 |
| 图片解码 | 浏览器原生 | `createImageBitmap`、`Image`、`canvas` |
| 打包 | Vite | 产出纯静态 `dist/`，可预览、可上传任意静态主机 |
| 部署（目标） | **Cloudflare Workers Static Assets**（主）/ **Pages**（兼容） | 全球 CDN；SPA fallback；WASM 按静态文件下发。转换不在边缘运行 |

**刻意不采用的方案：**

| 方案 | 不采用原因 |
|---|---|
| Node `potrace` / sharp / Puppeteer | 需要服务端，违背「图片不离开设备」 |
| canvg 作为默认渲染器 | 原生 `drawImage(svg)` 已覆盖本工具的图标/Logo 场景；仅当后续遇到原生渲染缺口再评估为降级 |
| `@svg-fns/svg2img` 等封装库 | 浏览器路径本质仍是 Canvas，多一层依赖无必要 |
| Cloudflare Pages Functions / Workers 做描摹或栅格化 | 违背「图片不离开设备」；边缘 CPU 时限也无法撑 WASM 描摹 |
| 默认接入 `@cloudflare/vite-plugin` | 本应用无服务端逻辑；插件会把本地 dev 绑到 Workers runtime，增加噪音。有 Worker（P2 URL 代理）时再加 |

### 4.4 SVG → 位图实现要点（浏览器已具备）

推荐路径（MDN：大图优先 `toBlob`，避免 `toDataURL` 撑爆内存）：

```ts
async function svgToBlob(
  svgText: string,
  { type, quality, width, height, background }: RasterOptions,
): Promise<Blob> {
  const blob = new Blob([svgText], { type: 'image/svg+xml;charset=utf-8' })
  const url = URL.createObjectURL(blob)
  try {
    const img = new Image()
    img.decoding = 'async'
    await new Promise<void>((resolve, reject) => {
      img.onload = () => resolve()
      img.onerror = () => reject(new Error('SVG 无法渲染'))
      img.src = url
    })

    const canvas = document.createElement('canvas')
    canvas.width = width
    canvas.height = height
    const ctx = canvas.getContext('2d')!
    if (background) {
      ctx.fillStyle = background
      ctx.fillRect(0, 0, width, height)
    }
    ctx.drawImage(img, 0, 0, width, height)

    const out = await new Promise<Blob | null>((resolve) =>
      canvas.toBlob(resolve, type, quality),
    )
    if (!out) throw new Error('导出失败')
    if (out.type !== type) throw new Error(`当前浏览器不支持导出 ${type}`)
    return out
  } finally {
    URL.revokeObjectURL(url)
  }
}
```

约束（必须写进校验与文案）：

1. **根节点必须能解析出宽高**（`width`/`height` 或 `viewBox`），否则 `drawImage` 结果为空。
2. **外链资源会污染 Canvas**，导出失败；上传时扫描 `<image href>`、`xlink:href`、外部 CSS。
3. **JPEG 无透明**：选 JPEG 时强制白色（或用户色）背景。
4. **编码能力探测**：对 `image/webp` 等请求导出后比对 `blob.type`，不一致则提示并回退 PNG。
5. **内存**：大倍率导出用 `toBlob` / `convertToBlob`，不用 `toDataURL`。
6. 大图栅格化可放入 Worker + `OffscreenCanvas.convertToBlob`（Safari 16.4+ 可用），作为性能优化而非功能前提。

### 4.5 位图 → SVG 实现要点

```ts
import { trace, posterize } from 'esm-potrace-wasm'

const svg = await trace(imageBitmap, { threshold, turdSize })
const svgColor = await posterize(imageBitmap, { steps, ... })
```

WASM 描摹放入 **Web Worker**，避免阻塞主线程。

### 4.6 性能与安全

- 描摹、大图栅格化均避免长时间占用主线程
- 单文件 20MB / 4096px 上限；SVG 导出像素面积同样按 4096 边长封顶
- 纯本地转换，图片不上传服务器；部署在 Cloudflare 时同样只下发静态资源，转换仍在用户浏览器内完成
- 用户下载的 SVG 若来自本工具描摹，仅含几何 path，无脚本；若用户上传的 SVG 再导出位图，栅格化过程本身不会执行 SVG 内脚本到下载文件中。预览插入 DOM 时，用户上传的 SVG 需按不可信内容处理（禁用脚本、避免 `v-html` 裸插）

| 空态 | 上传区居中 + 三种输入方式；文案同时提示「位图转 SVG / SVG 转 PNG·JPEG·WebP」 |
| 拖拽悬停 | 上传区边框高亮（el-upload 内置） |
| 校验失败 | `el-message` error + 3.3 提示语，上传区回空态 |
| 照片警告 | `el-alert` warning：「检测到照片类图片，描摹效果可能不佳」 |
| SVG 分流 | `el-alert` info：「已检测到 SVG，将导出为位图」并切换栅格化面板 |
| 转换中 | 按钮 loading + 预览区骨架屏 |
| 转换成功 | 对比视图滑入；体积增大时用警示色 |
| 转换失败 | `el-alert` error + 「重试」 |
| WebP 不支持 | 提示当前浏览器无法编码 WebP，自动改下 PNG |

### 5.4 响应式

- `< 768px`：参数面板移至结果区下方，上传区单列全宽
- 粘贴提示在移动端隐藏，保留点击选择

## 6. 边界情况与错误处理

| 场景 | 处理 |
|---|---|
| 粘贴内容非图片且非 SVG 文本 | 静默忽略 |
| 扩展名与实际格式不符 | 以解码 / XML 探测为准 |
| 描摹结果体积大于原图 | 正常返回，指标警示色 +「此图片不适合矢量转换」 |
| 全透明位图 | 提示「未检测到可见内容」 |
| SVG 无宽高 / viewBox | 提示「SVG 缺少尺寸信息，无法导出」 |
| SVG 含外链 | 拒绝导出并说明需内联 |
| JPEG 透明 | UI 禁止「透明背景」，默认白底 |
| 批量拖入多文件 | P1 只取第一个并提示；P2 支持队列 |
| 浏览器不能解码 WebP 输入 | 上传时拦截 |
| 浏览器不能编码 WebP 输出 | 探测后拦截或回退 PNG |

## 7. 工程配置与 Cloudflare 部署

本应用是 **纯静态 SPA**：构建产物只有 HTML/CSS/JS/WASM。Cloudflare 负责全球分发与 SPA 回退，**不执行转换**。脚手架必须一次配好，避免上线才改 `base`、WASM MIME、Worker 格式。

### 7.1 部署形态（先定，再写配置）

| 项 | 决定 |
|---|---|
| 运行时 | 浏览器。边缘侧无业务代码 |
| 主部署 | **Cloudflare Workers Static Assets**（`wrangler.jsonc` 只配 `assets`，不配 `main`） |
| 兼容部署 | **Cloudflare Pages**（同一份 `dist/`；用 `_redirects` 做 SPA fallback） |
| 本地开发 | 标准 `vite`，不依赖 Wrangler runtime |
| 预览生产包 | `vite preview` 与 `wrangler dev`（或 Pages preview）都可以验 `dist/` |
| 自定义域 | 根路径 `base: '/'`；若必须挂子路径，用 `VITE_BASE` 构建，禁止写死 |

Pages 与 Workers Assets 正在收敛。业务代码不引用 `process.env`、Node API、`cloudflare:` 模块，这样换主机（含非 Cloudflare）只需改部署配置。

### 7.2 `package.json` 约定

```json
{
  "name": "image-to-svg",
  "private": true,
  "type": "module",
  "engines": { "node": ">=22" },
  "packageManager": "pnpm@10",
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc -b && vite build",
    "preview": "vite preview",
    "deploy": "pnpm build && wrangler deploy",
    "cf:preview": "pnpm build && wrangler dev"
  }
}
```

- 包管理器锁定 `packageManager`，Cloudflare 构建才能复现锁文件。
- `build` 含类型检查，避免坏包上线。
- **不把** `reference/` 做成 workspace 包，避免被打进 `dist/`。

`.nvmrc` 写 `22`，与 Pages / Workers Builds 的 Node 镜像一致。

### 7.3 Vite：WASM、Worker、静态资源

描摹在 Web Worker 里跑 WASM。Vite 默认 worker 格式是 `iife`，生产构建会在 WASM / top-level await 上失败，必须在脚手架里改掉。

```ts
// vite.config.ts（要点，非完整文件）
export default defineConfig({
  base: process.env.VITE_BASE ?? '/',
  plugins: [vue(), wasm()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
  assetsInclude: ['**/*.wasm'],
  worker: {
    format: 'es',
    plugins: () => [wasm()],
  },
  build: {
    target: 'es2022',
    assetsInlineLimit: 0,   // WASM 保持独立文件，才能带上 application/wasm
    sourcemap: false,
    outDir: 'dist',
    emptyOutDir: true,
  },
})
```

约束：

1. **主线程 plugins 不会套到 Worker**。`vite-plugin-wasm`（或同类）必须同时出现在 `plugins` 与 `worker.plugins`。
2. Worker 用标准写法，便于被 Vite 打成独立 chunk：
   `new Worker(new URL('../workers/trace.worker.ts', import.meta.url), { type: 'module' })`
3. 禁止把 `.wasm` 内联成 base64：体积大、且 Cloudflare 无法按文件设 MIME。
4. `base` 只来自环境变量，保证 `*.workers.dev` / `*.pages.dev` / 自定义域都能加载 `/assets/*.wasm`。
5. 构建目标 `es2022`：现代浏览器 + `type: 'module'` Worker，不再兼容 IE。

### 7.4 Wrangler（Workers Static Assets）

无 `main` 字段 = 没有计费的 Worker 调用；导航请求由静态资源 + SPA fallback 消化。

```jsonc
// wrangler.jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "image-to-svg",
  "compatibility_date": "2026-08-25",
  "assets": {
    "directory": "./dist",
    "not_found_handling": "single-page-application"
  }
}
```

- `directory` 必须指向 Vite `outDir`（`dist`），不要指向仓库根或 `reference/`。
- `not_found_handling: "single-page-application"`：未匹配文件的导航回 `index.html`（200），前端路由才不会 404。
- 日后若加 URL 代理 Worker：再设 `main`，并用 `run_worker_first: ["/api/*"]`，静态页仍免费走 Assets。

`.gitignore` 至少包含：`node_modules/`、`dist/`、`.wrangler/`、`.env`、`.env.local`。密钥不进仓库；本应用现阶段也 **不需要** Cloudflare API Token 也能本地 `vite` 开发。

### 7.5 响应头与 Pages 兼容（`public/_headers`、`public/_redirects`）

Vite 会把 `public/` 原样拷到 `dist/`。Workers Assets 与 Pages 都读取这些文件。

`public/_headers`：

```
/
  Cache-Control: no-cache
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=()
  Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; connect-src 'self' blob:; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'

/index.html
  Cache-Control: no-cache

/assets/*
  Cache-Control: public, max-age=31536000, immutable

/*.wasm
  Content-Type: application/wasm
  Cache-Control: public, max-age=31536000, immutable
```

说明：

- `'wasm-unsafe-eval'`：在 CSP 下实例化 WASM 所必需；不要用宽泛的 `'unsafe-eval'`。
- `worker-src` 含 `blob:`：开发态 Worker 常用 blob URL；生产是 hashed `.js`，`'self'` 足够。
- `img-src` / `connect-src` 含 `blob:`：对象 URL 预览与下载。
- **不加** `Cross-Origin-Embedder-Policy: require-corp`：本工具不依赖 SharedArrayBuffer，加了会让外链预览、部分嵌入直接失败。
- `index.html` 不缓存，带 hash 的 `/assets/*` 长缓存。

`public/_redirects`（**仅 Pages 需要**；Workers 已用 `not_found_handling`）：

```
/*    /index.html   200
```

Cloudflare 构建设置（Pages 控制台或 `wrangler pages`）：

| 项 | 值 |
|---|---|
| Root directory | 仓库根（本应用），不是 `reference/` |
| Build command | `pnpm build` |
| Build output | `dist` |
| Node | 22（与 `.nvmrc` 一致） |

### 7.6 环境变量

| 变量 | 出现位置 | 用途 |
|---|---|---|
| `VITE_BASE` | 构建时 | 资源前缀，默认 `/` |
| `VITE_APP_TITLE` | 可选 | 页面标题 |

`.env.example` 只列 `VITE_*`。**禁止**把用户图片、转换结果、API 密钥放到 Cloudflare 环境变量或 KV。P2 URL 代理若启用，代理地址用 `VITE_PROXY_ORIGIN`，且文档写明「图片会经过边缘转发」。

### 7.7 TypeScript 与路径

- `strict: true`，`moduleResolution: bundler`，`noEmit` 给 `vue-tsc`。
- `@/*` → `src/*`，与 Vite alias 对齐。
- `src/env.d.ts` 声明 `*.wasm`、`*.vue`、`ImportMetaEnv`。
- 浏览器类型用 `DOM` + `WebWorker`；不要把 `@cloudflare/workers-types` 加进前端 `tsconfig`（没有 Worker 脚本）。

### 7.8 上线检查清单

1. `pnpm build` 后 `dist/assets/` 内有独立 `.wasm`，不是内联。
2. 用 `curl -I` 看 `*.wasm` 的 `Content-Type: application/wasm`（错误 MIME 会导致 `WebAssembly.instantiate` 失败）。
3. 刷新非根路径（若有路由）返回 200 + `index.html`，且 JS/WASM 请求不能被 SPA fallback 成 HTML。
4. 控制台无 COEP / CSP 拦截 Worker。
5. 转换前后 Network 面板没有把用户图片 POST 到任何主机。
6. `reference/`、`docs/`、`.git` 不在上传清单里。
